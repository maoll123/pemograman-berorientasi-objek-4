[7] BAB II: AUDIT CLASS P2 & PERANCANGAN ARSITEKTUR ENKAPSULASI

[8] 2.1 Analisis Masalah & Kelemahan Arsitektur P2: Pada implementasi Praktikum 2, class yang dibangun belum menerapkan prinsip pembungkusan data (Information Hiding). Hal ini menimbulkan beberapa celah teknis serius, antara lain:

[9] 1. Akses Bebas Tanpa Filter (Direct Access Vulnerability): 

[10] Attribute dapat dimodifikasi langsung dari luar class menggunakan operator titik (misal: kendaraan1.tarifPerHari = -100000;). Akibatnya, nilai negatif atau data rusak dapat masuk ke dalam state objek.

[11] 2. Constructor Mengabaikan Aturan Bisnis (Unchecked Constructor): 

[12] Nilai parameter langsung di-assign ke field (this.tarifPerHari = tarifPerHari;) tanpa melewati mekanisme validasi pra-syarat.

[13] 3. Ketiadaan Kontrol Hak Akses (No Read-Only Protection): 

[14] Attribute identitas seperti Nomor KTP, ID Pelanggan, dan Kode Transaksi dapat diubah sewaktu-waktu oleh pihak luar yang menyebabkan hilangnya integritas audit.

[16] 2.3 Identifikasi Hak Akses: Read-Only, Read-Write & Validasi Khusus

[17] Prinsip Klasifikasi Hak Akses: Berdasarkan analisis kebutuhan fungsional dan keamanan data, hak akses setiap attribute diklasifikasikan ke dalam 3 kelompok strategis:

[18] 1. Attribute Read-Only (Hanya Menyediakan Getter, Tanpa Setter Publik):
   • Pelanggan.idPelanggan : ID unik pelanggan tidak boleh dimanipulasi setelah object terdaftar.
   • TransaksiSewa.kodeTransaksi : Nomor registrasi transaksi bersifat permanen (immutable audit trail).
   • TransaksiSewa.totalBiaya : Total biaya dikomputasi oleh logika bisnis sistem, tidak boleh diedit manual.
   • Pelanggan.totalSewaAktif : Hanya dimutasi secara terproteksi melalui method tambahSewaAktif() dan kurangiSewaAktif().

[19] 2. Attribute Read-Write (Menyediakan Getter dan Setter Ber-Validasi):
   • Kendaraan.tarifPerHari : Dapat disesuaikan sewaktu-waktu namun wajib >= Rp 50.000,00.
   • Kendaraan.platNomor : Dapat diperbarui dengan pola baku Regex Plat Nomor Indonesia.
   • Pelanggan.namaLengkap : Dapat diperbarui dengan validasi minimal 3 karakter non-blank.
   • Pelanggan.nomorTelepon : Dapat diperbarui melalui perbaruiKontak() dengan validasi pola '08' 10–14 digit.
   • TransaksiSewa.durasiHari : Dapat diperpanjang melalui perpanjangDurasi() dengan validasi tambahanHari > 0.

[20] 3. Aturan Validasi Khusus (Defensive Programming):
   • Pengecekan pra-syarat transaksi: Transaksi sewa ditolak jika armada sedang disewa atau kuota pelanggan penuh.
   • Constructor Defensif: Constructor tidak melakukan assignment langsung melainkan memanggil setter untuk menyaring data awal.

[37] 4.2 Analisis Teknis & Pembahasan Hasil Pengujian

[38] 1. Keberhasilan Validasi Data Masukan (Input Validation Barrier):
   Ketika method mutator menerima nilai yang melanggar aturan bisnis (seperti tarif negatif Rp -500.000, plat nomor 'JAKARTA-123', nama kosong, NIK 5 digit, atau durasi perpanjangan negatif), setter secara tegas menolak pembaruan tersebut, mencetak pesan diagnostik [VALIDATION ERROR], dan mempertahankan nilai state sebelumnya tanpa distorsi data.

[39] 2. Keberhasilan Information Hiding & Controlled Access:
   Seluruh pembacaan data kini dilakukan secara tertib melalui Getter method. Tidak ada lagi baris kode di Main.java yang mengakses attribute secara direct (misal: mhs.ipk = -10; seperti pada review modul). Hal ini membuktikan implementasi prinsip Encapsulation telah tercapai secara paripurna.

[40] 3. Integritas Hubungan Antar Objek (Object Association Consistency):
   Saat transaksi dibuat, status armada dan kuota pelanggan termutasi secara sinkron. Pada Test Invalid 7, sistem berhasil mencegah pembuatan transaksi baru pada unit L 1234 AB yang sedang berstatus 'Sedang Disewa (Booked)', sehingga double-booking armada mustahil terjadi.

[44] 🌟 What Went Well? (Apa yang berjalan baik?)
Penerapan prinsip Information Hiding dan Encapsulation berhasil direalisasikan secara sempurna pada seluruh class. Refactoring constructor menjadi defensif terbukti efektif mencegah inisialisasi object dengan data corrupt. Pemisahan pengujian antara Positive Test dan Negative Test memberikan visibilitas yang sangat jelas terhadap ketangguhan sistem dalam menyaring input ilegal.

[45] ⚠️ What Went Wrong? (Apa kendala dalam refactoring?)
Penanganan relasi dependensi antar objek saat validasi transaksi memerlukan pengecekan kondisi null dan state ketersediaan secara hati-hati agar tidak memicu NullPointerException saat instansiasi gagal. Namun hal ini berhasil diatasi dengan Defensive Null Checks.

[46] 🚀 Improvement & Target Sprint Berikutnya (P4):
Pada Sprint berikutnya (P4 – Relasi Antarobject / Asosiasi, Agregasi, dan Komposisi), struktur relasi antar class akan diperdalam dengan memodelkan array daftar armada dalam satu rental pool (Agregasi) dan memisahkan modul pencatatan riwayat transaksi secara terstruktur.

  import java.util.regex.Pattern;

/**
 * Class Kendaraan
 * Merepresentasikan armada kendaraan dalam AutoRent System.
 * Menerapkan prinsip Encapsulation dengan seluruh attribute private,
 * validasi data pada setter/constructor, dan pembatasan akses langsung.
 *
 * @author Ahmad Yasar Maulana Dais (NRP: 3125522018)
 * @version 3.0 (Modul 3 - Encapsulation & Validation)
 */
public class Kendaraan {
    // 1. Enkapsulasi: Seluruh attribute dideklarasikan dengan access modifier 'private'
    private String platNomor;
    private String merk;
    private String jenis;
    private double tarifPerHari;
    private boolean isTersedia;

    // Pola regex plat nomor Indonesia (contoh: "L 1234 AB", "B 9999 XYZ", "M 123 CD")
    private static final String REGEX_PLAT_NOMOR = "^[A-Z]{1,2}\\s[0-9]{1,4}\\s[A-Z]{1,3}$";
    private static final double MIN_TARIF_PER_HARI = 50000.0;

    // 2. Parameterized Constructor yang menerapkan Defensive Programming (memanggil validasi setter)
    public Kendaraan(String platNomor, String merk, String jenis, double tarifPerHari, boolean isTersedia) {
        // Menggunakan setter agar seluruh nilai awal wajib lolos aturan validasi data
        if (!setPlatNomor(platNomor)) {
            this.platNomor = "N/A (Invalid Plat)";
        }
        if (!setMerk(merk)) {
            this.merk = "Unit Standar (Default)";
        }
        if (!setJenis(jenis)) {
            this.jenis = "MPV (Default)";
        }
        if (!setTarifPerHari(tarifPerHari)) {
            this.tarifPerHari = MIN_TARIF_PER_HARI;
        }
        this.isTersedia = isTersedia;
    }

    // 3. Getter Methods (Controlled Read Access)
    public String getPlatNomor() {
        return platNomor;
    }

    public String getMerk() {
        return merk;
    }

    public String getJenis() {
        return jenis;
    }

    public double getTarifPerHari() {
        return tarifPerHari;
    }

    public boolean isUnitTersedia() {
        return isTersedia;
    }

    // 4. Setter Methods dengan Validasi Data Bisnis (Controlled Mutator Access)
    
    /**
     * Validasi 1: Format Plat Nomor Polisi
     * Plat nomor harus sesuai pola standar kepolisian (1-2 huruf kode wilayah, 1-4 digit angka, 1-3 huruf seri).
     */
    public boolean setPlatNomor(String platNomor) {
        if (platNomor != null && Pattern.matches(REGEX_PLAT_NOMOR, platNomor.trim().toUpperCase())) {
            this.platNomor = platNomor.trim().toUpperCase();
            return true;
        } else {
            System.out.println("  [VALIDATION ERROR] Plat nomor '" + platNomor + "' TIDAK VALID! Format baku harus sesuai: [Kode Wilayah] [Nomor] [Seri], contoh: 'L 1234 AB'");
            return false;
        }
    }

    /**
     * Validasi 2: Merk / Tipe Kendaraan
     * Merk tidak boleh null, tidak boleh kosong/hanya spasi, dan minimal 3 karakter.
     */
    public boolean setMerk(String merk) {
        if (merk != null && merk.trim().length() >= 3) {
            this.merk = merk.trim();
            return true;
        } else {
            System.out.println("  [VALIDATION ERROR] Merk kendaraan '" + merk + "' TIDAK VALID! Nama merk tidak boleh kosong dan minimal 3 karakter.");
            return false;
        }
    }

    /**
     * Validasi 3: Jenis / Kategori Armada
     * Kategori kendaraan tidak boleh null atau kosong.
     */
    public boolean setJenis(String jenis) {
        if (jenis != null && !jenis.trim().isEmpty()) {
            this.jenis = jenis.trim();
            return true;
        } else {

    public TransaksiSewa(String kodeTransaksi, Kendaraan kendaraan, Pelanggan pelanggan, String tanggalSewa, int durasiHari) {

            this.durasiHari = 0;
            this.totalBiaya = 0.0;
            return;

            this.pelanggan = pelanggan;

            this.totalBiaya = 0.0;
